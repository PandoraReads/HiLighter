# pandora-hilight — 笔记精华高亮 + 辅导卡片

## 原理（已逆向确认，v2.0.2）

HiLighter 的 Markdown 高亮是**双写**：
1. **卡片**：IndexedDB，批量写入通道 `.hilighter/sync-data.json`（version 2）+
   命令/协议 `obsidian://hilighter?op=sync-import`（按 id upsert）。
2. **正文上色**：笔记正文内 `text` 被包成
   `<mark class="hl-highlight hl-h-<color>" data-id="<id>" data-hl-color="#<hex>">text</mark>`
   —— 有颜色、点击卡片能定位的关键；`data-id` 与卡片记录一致。

本技能流程：**选精华 → 生成记录 JSON → 脚本写正文 `<mark>` + 合并 sync 文件 + 自动
触发导入**。记录字段与定位规则详见 `references/hilighter-format.md`（生成记录前必读）。

## 流程

### 第 1 步：读文本，判类型

读取目标笔记，判定文本类型（决定密度与选取策略）：

| 类型 | 特征 | 默认密度 | 选取倾向 |
|---|---|---|---|
| 视频/播客转录 | `[MM:SS]` 时间戳行 | 3-6 条/千字 | 完整观点句，跳口头语与重复 |
| 英文原版（书/外刊） | 大段英文 | 5-8 条/千字 | 论点句 + 地道表达；术语必给翻译 |
| 中文文章/公众号 | 常规段落 | 5-8 条/千字 | 核心论点、反常识观点 |
| Wiki/概念页 | frontmatter 类型: Wiki* | 2-4 条/千字 | 定义句、关键证据 |
| 长篇（>5000 字） | 任意 | 降到 2-3 条/千字 | 只留骨架级精华 |

### 第 2 步：商定参数（每次必问，一轮问完）

1. **密度**：按上表默认值推荐 + 高/低两档备选。
2. **范围**：全文 / 指定章节或行范围。
3. **辅导笔记构成**：默认「知识点注释 + 启发性提问 + 外语术语翻译」全开，可关。
4. 文本是外语学习材料时追加一问：术语翻译是否附**使用语境**（默认附）。

用户直接给了明确参数（如"稀疏一点""只标第二章"）时跳过对应问题。

### 第 3 步：选精华 + 写辅导笔记

**颜色语义**：

| color | 类型 | note 必含 |
|---|---|---|
| `yellow` | 核心观点/重点 | 注释 +（适用时）提问 |
| `blue` | 概念/术语 | 定义式注释；外语术语加中文释义 + 使用语境 |
| `green` | 方法/可执行步骤 | 注释 + 落地提示 |
| `pink` | 金句/灵感 | 提问（"这句能怎么用到你的项目里？"式）|

**note 写法**（→ 插件右侧卡片正文，Markdown）：
- 用无序列表 `- ` 逐条写，**不加「注释/提问/翻译」等字样**，顺序固定为
  注释 → 提问 → 术语翻译（无术语则省略第三行）：
  ```markdown
  - 一两句说清为什么重要/背景。
  - 一个促进主动回忆的问题？（贴合 Active Recall）
  - term = 中文释义（使用语境）
  ```
- 简短克制，每张卡片 ≤ 80 字（术语翻译除外）。

**选取铁律**：
- `text` 必须是源文件**某一行内的精确子串**（逐字符一致，含标点；不能跨行、不能改写）。
- 一条高亮一个完整语义单元（短语到一句话），不标半截从句。
- **跳过 frontmatter**（`---` 区块内不选句）。
- 宁缺毋滥：可标可不标的不标。
- 库内旧高亮的 lineIndex 可能因文件后续编辑而漂移——**以当前文件实际行号为准**，不参考 sync 文件里旧记录的行号。

### 第 4 步：生成记录并合并导入

1. 用 Read 精确定位每条 text 的行号，`lineIndex` 为 **0 基**（Read 显示的行号减 1）。
2. 记录数组写入临时文件 `/tmp/hilight-<slug>.json`（格式见 references）。
3. 执行：

```bash
python3 "<本技能目录>/scripts/hilight_merge.py" /tmp/hilight-<slug>.json \
  --vault "/用户确认的/Obsidian/仓库绝对路径"
```

脚本校验行内子串、按 (sourcePath,lineIndex,text) 去重、写正文 `<mark>`（已包过则跳过；
`00_inbox/` 只读层拒绝写 mark，可用 `--no-marks` 只出卡片）、合并进 sync 文件，并自动
`open obsidian://hilighter?op=sync-import` 触发导入（HiLighter ≥2.0.2 自有协议，
无需第三方插件）。

4. 结果处理：
   - `autoImport: true` → 完成，报告条数与颜色分布。
   - `manualStep` 出现（协议不可用/低于 2.0.2）→ 告知用户在命令面板跑
     「导入同步数据」。
   - 脚本报「定位失败」→ 该条 text 与行号不匹配，回第 3 步修正后重跑（sync 文件
     未被污染，脚本校验失败即退出）。

### 完成后输出

报告：文本类型、商定密度、实际条数（按颜色分布）、跳过去重数、导入方式（自动/手动），
并提醒用户打开该笔记即可看到高亮与右侧卡片。
